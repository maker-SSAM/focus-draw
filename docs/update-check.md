# 새 버전 확인 (배포판 2.0부터)

2026-10-07 선생님 결정. 윈도우 판과 맥 판이 **똑같이** 넣는다.

## 배경

- 윈도우 1.0(`v1.0.0`, GitHub 릴리스 Latest)에는 인터넷에 닿는 코드가 전혀 없다. 그래서 1.0을 받은 선생님들은 앱 안에서 새 버전 소식을 받을 수 없다.
  → 2.0이 나오면 **처음 나눠 드린 경로**(메신저·커뮤니티·메일)로 따로 알린다. 2.0 안내문에 "이제 설정 창에서 새 버전을 확인할 수 있다"를 적는다.
- 2.0부터 확인 단추가 있으면 그다음 버전(2.1, 3.0 …)부터는 앱 안에서 확인할 수 있다.
- 맥 판도 곧 GitHub에 배포한다(2026-10-07). 두 판이 같은 저장소(`maker-SSAM/focus-draw`)의 릴리스를 쓴다.

## 정한 것 (선생님 결정)

1. **"새 버전 확인" 단추 하나만** 둔다. 선생님이 단추를 누를 때만 인터넷에 접속한다.
2. **하지 않는 것**: 자동 업데이트, 앱이 스스로 내려받거나 설치하기, 켤 때·하루 한 번 등 **자동 확인과 알림**. 트레이·위젯·창에 저절로 뜨는 안내도 없다.
3. 그래서 **설정 항목은 늘지 않는다**(`settings.ini`는 그대로 — 켜고 끄는 옵션이 필요 없다).

## 동작 (두 판 공통)

- **자리**: 설정 창의 정보 칸. 윈도우는 아래쪽 "제작자: maker_SSAM" 줄 근처, 맥은 일반 탭 "정보" 상자의 버전 줄 옆.
- **누르면**: 버전 파일 하나(아래)를 HTTPS로 읽어 지금 버전과 견준다. 기다리는 시간은 5초까지. 그동안 단추는 "확인 중…"으로 바뀌고 다시 누를 수 없다. 수업 화면(드로잉·강조)은 막지 않는다.
- **결과는 단추 옆 글자로만** 알린다 (따로 창을 띄우지 않는다):
  - 최신: "최신 버전입니다 (2.0.0)"
  - 새 버전: "새 버전 2.1.0이 있습니다" + **[받는 곳 열기]** 단추 → 기본 웹 브라우저로 릴리스 쪽을 연다. 내려받기와 설치는 선생님이 한다.
  - 실패(인터넷이 없거나 학교망이 막음, 파일 모양이 이상함): "확인하지 못했습니다. 받는 곳에서 직접 확인하세요" + [받는 곳 열기]. 오류 창이나 소리는 내지 않는다.
- **보내는 정보 없음**: 파일 하나를 읽기만 한다. 설정·기기 정보·사용 기록을 보내지 않는다(웹 요청이므로 GitHub은 접속 IP를 볼 수 있다 — 안내문에 한 줄).
- 버전 비교는 숫자 단위로(`2.10.0` > `2.9.0`). 지금 버전이 더 높으면(개발판) "최신 버전입니다".

## 버전 파일

GitHub "Latest" 릴리스는 한 판만 가리킬 수 있고(지금 `mac/RELEASE.md`는 Latest를 윈도우로 지킨다), 두 판이 다른 날에 나올 수 있다. 그래서 릴리스 목록 대신 **저장소 맨 위의 글 파일 하나**를 읽는다.

- 위치: `version.txt` (저장소 맨 위, master) → `https://raw.githubusercontent.com/maker-SSAM/focus-draw/master/version.txt`
- 모양: `이름=값` 줄 (AutoHotkey에 JSON 읽기가 없어 가장 단순한 모양으로). 모르는 줄과 `;` 주석은 무시.
  ```
  windows=2.0.0
  windows_url=https://github.com/maker-SSAM/focus-draw/releases/tag/v2.0.0
  mac=2.0.0
  mac_url=https://github.com/maker-SSAM/focus-draw/releases/tag/v2.0.0
  ```
- 새 버전을 올릴 때 **릴리스를 만든 뒤 마지막에** 그 판의 두 줄을 고쳐 push한다(파일을 먼저 고치면 아직 없는 릴리스를 가리킨다). raw 주소는 몇 분 늦게 바뀔 수 있다.
- `_url`이 없거나 이상하면 `https://github.com/maker-SSAM/focus-draw/releases`를 연다.
- 이 파일은 저장소 맨 위라 맥·윈도우 어느 세션이 고쳐도 된다(배포 절차의 한 단계로). 만드는 것은 2.0 첫 배포 때.

## 판별 구현 메모

- **맥**: `URLSession`(타임아웃 5초), 결과는 메인 스레드에서 설정 창 글자로. 권한이 필요 없는 일반 네트워크라 세션 금지 사항(손쉬운 사용·화면 기록 등)에 걸리지 않는다. 받는 곳은 `NSWorkspace.shared.open`. 지금 버전은 `AppInfo.displayVersion`(`CFBundleShortVersionString`).
- **윈도우**: `ComObject("WinHttp.WinHttpRequest.5.1")`을 비동기(`Open(..., true)` + `WaitForResponse(0)`를 타이머로 살핌)로 써서 설정 창이 굳지 않게. 받는 곳은 `Run(url)`. 지금 버전은 `APP_VERSION`.
- 자체 점검(맥): 버전 비교 함수와 파일 읽기(줄 모양·주석·빠진 줄)는 글 점검으로. 실제 인터넷 접속은 점검에서 하지 않는다.

## 버전 번호 (2026-10-07 결정)

- 맥도 **2.0.0**으로 맞춘다. 두 판을 함께 진행해 같은 날 **한 릴리스 `v2.0.0`**에 두 zip을 올린다(맥 1.0은 따로 내지 않는다). 그래서 위 예시의 두 주소가 같다.
- 그 뒤로도 두 판을 함께 내면 번호가 같게 유지된다. 한 판만 고쳐 내는 일이 생기면 `version.txt`의 그 판 줄만 바꾸면 된다(파일은 두 판 번호가 달라도 동작한다).
- 2.0 전 맥 시험판(베타 2 `mac-v0.9.0` 등)은 지금 `mac/RELEASE.md`대로 시험판·Latest 아님으로 올린다. 2.0 정식 배포 절차는 `mac/design/stages.md`의 S12.
