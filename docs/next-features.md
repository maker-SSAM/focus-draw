## 선생님 계획 (2026-10-09)

1. 기능 추가: 확대, 핀홀 조명, 타이머.
2. **확대**: 윈도우 기본 돋보기 / 맥 기본 확대를 쓰되, 위젯 버튼을 눌러 켠다. 옵션도 연동한다.
3. **핀홀 조명**: 강조 기능과 비슷하다. 마우스 커서를 숨기고 십자 커서를 넣은 뒤, 강조할 부분만 밝게 두고 나머지는 어둡게 한다. 어두운 부분의 투명도를 설정할 수 있다.
4. **타이머**: 위젯 버튼으로 실행한다. 뽀모도로 타이머 그래픽 + 전자시계. 전체 화면 / 작은 화면 중에서 고른다.
5. **위젯 펼치기**: 버튼이 늘어나므로, 위젯 ⋮ 버튼 왼쪽에 작은 `<` 화살표를 달고 누르면 위젯이 길게 펼쳐진다.

### 확대

- **윈도우: 쉽다.** 2026-09-22에 이미 시험했다(`windows/NOTES.md` "확대(돋보기) — 실제로 시험해보고"). 돋보기 설정은 `HKCU\Software\Microsoft\ScreenMagnifier`에 있고 우리가 쓸 수 있다.
  - `Magnification`(배율 %), `MagnificationMode`(2 = 전체 화면, 3 = 렌즈), `LensWidth`/`LensHeight`, `ZoomIncrement`, `FollowMouse`, `RunningState`.
  - 켜져 있는 동안에도 바로 반영되고, 값은 양방향이다(사용자가 `Win`+`+`로 바꾸면 그 값이 다시 적힌다). 확대한 화면 위에 그리기도 배율 그대로 맞다.
  - 켜기는 `magnify.exe` 실행 또는 `Win`+`+`. **끄기는 강제 종료가 안 된다**(UIAccess) — `Win`+`Esc`를 보내는 방식으로 다시 시험할 것.
  - 위험: 이 레지스트리 이름은 Microsoft가 공식으로 약속한 것이 아니다. 바뀌면 옵션 연동만 조용히 안 먹고 돋보기 자체는 뜬다.
- **맥: 버튼으로 켜기·옵션 연동 모두 사실상 불가능하다.**
  - 앱이 맥 기본 확대를 켜는 공개 방법이 없다(`UAZoomEnabled()`는 읽기만 한다). ⌥⌘8을 대신 보내려면 손쉬운 사용 권한 + `CGEventPost`가 필요한데, 둘 다 `focus-draw/CLAUDE.md`의 맥 금지 사항이다.
  - 확대 옵션은 시스템이 보호하는 설정(`com.apple.universalaccess`)이라 앱이 고칠 수 없다.
  - 직접 확대를 만들면 화면 기록 권한이 필요하다 — 이것도 금지 사항.
  - 남는 방법: 맥 버튼은 "⌥⌘8을 누르세요" 안내 + "시스템 설정 → 손쉬운 사용 → 확대/축소 열기" 단추만 둔다.
- 설정 파일: 윈도우만 쓰는 확대 항목이 생긴다. "두 판 설정 파일이 같다" 원칙을 지키려면 맥은 `[Highlight] HideCursor`처럼 읽고 쓰기만 하고 쓰지는 않는다.

### 핀홀 조명

- **화면을 읽지 않고 그리기만 한다.** 화면 캡처 권한·노란 테두리 문제가 없다.
  - 윈도우: 전체 화면을 덮는 반투명 검정 창(클릭 통과)에 구멍을 뚫고 마우스를 따라 옮긴다. `WinSetRegion`이면 아주 가볍다(가장자리는 각짐). 부드러운 가장자리는 화면 크기 판을 매번 올려야 해서 더 무겁다(`UpdateLayeredWindow`는 화면 주사율에 묶인다 — NOTES 측정 참고).
  - 맥: 테두리 없는 창 + 구멍 모양 마스크(Core Animation). 권한 필요 없음.
- **십자 커서는 이미 있다.** 맥은 강조 중 커서를 늘 숨기고 원 가운데 검정 십자를 그린다(맥 ROADMAP 결정 10). 윈도우는 `[Highlight] HideCursor`.
- **추천: 새 기능이 아니라 강조의 두 번째 모양으로.** "강조 모양: 원 테두리 / 핀홀 조명". 크기 설정과 단축키(F8)를 같이 쓰고, 위젯 버튼이 늘지 않는다. 둘을 수업 중 빠르게 오가야 할 때만 버튼을 따로 둔다.
- 새 설정은 두 개면 충분: 어두운 부분 진하기, 가장자리 부드럽게(켬/끔).
- 쉬는 동안 도는 타이머 0개 원칙: 핀홀이 켜져 있을 때만 마우스를 따라간다(지금 강조와 같음).

### 타이머

- **2026-09-21에 세운 기준과 부딪힌다**(`windows/NOTES.md`): 기능을 넣을지는 "화면의 무언가에 주목시키는 동작인가?"로 판단하고, "타이머·녹화·캡처 저장 같은 것은 수업용이어도 목적이 달라 거절한다". 넣는다면 기준을 바꾼다는 결정을 여기 한 줄 남긴다.
- **세 기능 중 일이 가장 많다.** 뽀모도로 그래픽, 전자시계, 시간 입력, 일시정지, 끝 알림(소리?), 전체 화면/작은 창, 창 위치 기억 — 모두 AHK와 Swift로 두 번 만들고 점검까지 맞춰야 한다.
- 쉬는 동안 타이머 0개 원칙은 지킬 수 있다: 타이머 창이 떠 있을 때만 1초마다 돈다.
- 넣는다면 작게 시작: 작은 창 하나 + 시간 고르기(1/3/5/10분) + 시작·멈춤. 전체 화면은 그다음.

### 위젯 `<` 펼치기

- 걱정되는 점
  - 숨긴 버튼은 잘 안 쓰게 된다 — "한 번 누르면 바로"가 위젯의 장점인데 두 번 눌러야 한다.
  - 전자칠판에서 ⋮ 옆 작은 화살표는 손가락으로 누르기 어렵다.
  - 위젯이 화면 왼쪽 끝에 있으면 왼쪽으로 펼칠 때 잘린다.
  - 펼친 상태를 기억할지 등 상태가 하나 늘어난다.
- **추천: 설정 창에서 "위젯에 보일 버튼"을 체크로 고르게 한다.** 선생님마다 쓰는 기능만 늘 보인다. 기본값은 지금처럼 강조·드로잉·설정. 핀홀을 강조 모양으로 넣으면 늘어나는 버튼은 많아야 확대·타이머 두 개다.
