## 프로젝트 개요
**Focus & Draw (포커스 앤 드로우)** — AutoHotkey v2로 만든 수업용 화면 도구 (단일 파일 [focus-draw.ahk](focus-draw.ahk)).
spotmouse의 마우스 하이라이트 기능과 ZoomIt의 화면 드로잉 기능 중 핵심만 가볍게 구현. GitHub 저장소: `maker-SSAM/focus-draw`.
- 마우스 강조(스포트라이트) + 클릭 시 링 애니메이션
- 화면 판서: 자유선 / 직선(Shift) / 사각형(Ctrl) / 원(Ctrl+Shift) — ZoomIt과 동일한 키 조합
- 설정 창(`settings.ini`에 저장), 트레이 바로가기 아이콘 2개, 단축키

    ```
    PEN_FLAG_BARREL   0x01  옆면 버튼
    PEN_FLAG_INVERTED 0x02  펜을 뒤집어 뒤쪽이 화면을 향함
    PEN_FLAG_ERASER   0x04  뒤쪽이 화면에 닿음
    ```
    `IsEraserEnd()`에서 `GetPointerPenInfo`로 읽고 INVERTED·ERASER만 본다. **옆면 버튼(BARREL)은 일부러 뺐다** — 펜을 고쳐 쥐다 버튼이 눌리면 의도치 않게 지워진다
  - **앞뒤 판단은 닿는 순간 한 번만** 하고 획이 끝날 때까지 유지한다. 긋는 도중에 계속 물어보면 펜이 기울어져 플래그가 한 프레임 흔들릴 때 **한 획이 반은 글씨 반은 지우개**가 된다
  - 뒤쪽일 때는 `EraseSegment`를 쓰고 커서도 지우개 테두리 원으로 바꾼다. 펜을 떼면 `SetBrushMode("pen")`으로 되돌린다 — 안 되돌리면 다음 획까지 지우개 커서로 남는다
  - **펜 정보를 못 얻으면 조용히 "앞쪽"으로 친다.** 적외선 방식 보드의 펜은 그냥 막대라 Windows에는 손가락과 구분이 안 되는데, 못 알아들었다고 안 그려지는 것보다 평소대로 그려지는 쪽이 낫다
  - **검증의 한계 — 이건 실제 기기에서만 확인된다.** 합성 펜 입력을 시도했으나(`CreateSyntheticPointerDevice(PT_PEN)` + `InjectSyntheticPointerInput`) **주입은 성공(1)을 반환하는데 창에 메시지가 한 건도 오지 않았다.** hover(INRANGE) 프레임을 먼저 넣어봐도 같았다. 합성 **터치**는 멀쩡히 전달되는 것과 대조적이다 — 합성 펜은 이 환경에서 창까지 닿지 않는다고 보고 접었다
    - 대신 확인한 것: **터치 경로가 안 깨졌다.** 펜 정보가 없는 터치에서 `IsEraserEnd`가 false를 돌려주고 기존 6개 항목(터치 그리기 / Ctrl+Z 한 번 / 마우스 정상 / 섞어쓰기 / Esc)이 전부 그대로 통과한다
  - 그래서 **확인 도구를 같이 만들었다**: `터치펜-확인.ahk`. 모든 모니터를 덮는 창을 띄우고, 닿는 입력마다 포인터 종류·펜정보 유무·penFlags·필압을 보여주며 **서로 다른 종류가 몇 가지 나왔는지** 누적한다. 앞쪽과 뒤쪽이 다르게 나오면 구분 가능한 기기다. Esc를 누르면 `터치펜-확인-결과.txt`로 남는다. 합성 터치로 동작을 확인했다(접촉 7회, "터치(2) / 펜정보 없음 / 플래그 없음" 1가지)

    - 도형은 한 번 그릴 때마다 전체를 다시 그리므로, 포인터 메시지가 올 때마다 그리지 않고 **자리만 적어두고 `DrawPoll`이 10ms마다 마지막 자리로 다시 그린다**(칠판은 마우스보다 메시지를 훨씬 자주 보내서 다 그리면 밀린다). 손을 뗄 때(`OnPointerUp`) 마지막 모습을 한 번 더 그린다
    - 터치로 긋는 동안에는 `DrawPoll`이 커서 원을 진짜 커서 자리로 옮기지 않는다 — 포인터 자리로 옮긴 원을 뒤처진 커서 자리로 되돌려 떨리던 것
    - 레이저 점도 터치로 긋는 동안에는 포인터 좌표를 따른다
  - **A·S는 한 번 누르면 계속 유지**(`PEN_KIND_KEYS`, `penKind`, `SetPenKind`). 칠판 앞에서는 키를 쥔 채 그을 수 없기 때문이다. 숫자키(1~9, 0)를 누르면 보통 펜으로 돌아오고(`SetDrawColor`), 드로잉을 껐다 켜도 돌아온다. 도형 키를 쥐고 그으면 특수 펜보다 도형이 먼저다. 사라지는 펜을 고른 동안에는 레이저 점이 계속 뜨므로, 남은 꼬리가 없고 점이 그대로면 `LaserTick`이 다시 그리지 않고 바로 돌아간다
  - 덤: `ToggleDraw`가 `activeDrawAlpha`를 global 선언 없이 대입하고 있어서 휠로 바꾼 투명도가 껐다 켜도 안 돌아오던 것을 고쳤다
  - 안내(README, `읽어주세요.txt`, 단축키 그림 `shortcuts.png`)의 "A·S + 드래그"를 "한 번 누르면 유지"로 고쳤다

- **zip이 두 가지다.** `배포용/Focus & Draw.zip`(직접 나눠주는 것 — 읽어주세요.txt에 문의처 줄 있음)과 GitHub 릴리스의 `Focus-Draw-<버전>.zip`(공개 — **문의처 줄 없는 저장소의 txt**). 안의 구성은 둘 다 `Focus & Draw/focus-draw.exe` + `Focus & Draw/읽어주세요.txt`. 2026-09-28에 v1.0.0 릴리스의 zip과 태그를 새 판으로 교체했다(사용자 결정 — 널리 퍼지기 전이라 버전을 올리지 않음). 태그는 주석 없는 태그
- 프로젝트 폴더의 exe가 실행 중이면 덮어쓸 수 없다 — 트레이 메뉴의 "종료"로 닫고 한다(강제 종료하면 커서가 안 돌아온다)
