# S1b 메모 — 시험 장치를 이렇게 만들었다

2026-09-29, Opus 5.5. S1c·S3·S4가 알아야 할 결정과 남은 문제만 적는다.

## 결정

- **실험 스위치는 settings.ini가 아니라 UserDefaults(`exp.*`)에 둔다.** Windows와 같이 쓰는 설정 파일을 더럽히지 않는다. `build.sh`(개발)·`--quick`·`--test`는 `-D EXPERIMENTS`로 "실험" 메뉴를 넣고, `--release`는 빼서 늘 기본값(B안, NSWindow, 지금 창 동작, 시스템 커서)으로 돈다.
- 자체 점검·`--bench`는 `Experiments.memoryOnly`로 스위치를 메모리에만 적어 사용자 설정을 건드리지 않는다. 진단 기록도 켜지 않는다.
- **메뉴는 위젯 오른쪽 클릭(⌃ 클릭)으로도 연다.** 노치 뒤로 아이콘이 숨는 맥북(선생님 맥북에서 실제로 일어남) 때문.
- **B안의 돌려주기**: macOS 14+에서 `NSApp.yieldActivation(to:)` 뒤 `activate(from:options:)`. 13은 예전 `activate()`.
- **C안 키 목록 (47개)**: 숫자 1~0·키패드 숫자, Q W E R A S, delete·앞으로 지우기·Esc, Z X C(그냥·⇧, 누름+뗌), = (그냥·⇧·⌥·⌥⇧), −·키패드+·키패드−(그냥·⌥), ⌘Z·⌃Z. 드로잉을 켤 때 등록, 끌 때(`turnOff` 한 곳) 전부 해제.
  - 안전장치: 드로잉이 꺼진 뒤 드로잉 키가 한 번이라도 오면 그 자리에서 전부 풀고 `HK STRAY`를 남긴다. 앱이 죽으면 시스템이 알아서 푼다.
  - 크기 키(+/−)는 시스템 반복이 오면 그걸 쓰고, 안 오면 0.45초 뒤 0.07초마다 스스로 반복한다. 어느 쪽이었는지 기록에 남는다.
- **커서 숨기기**: 비공개 `SetsCursorInBackground` + `CGDisplayHideCursor`. 이유(board·spot)를 모아 `SystemCursor` 한 곳에서만 숨김/보임을 불러 짝이 맞게 한다. 종료할 때 `showAll()`. 판 커서는 판 밖(위젯 위 등)으로 나가면 화살표를 돌려준다.
- **판 창 종류**: B = `InkWindow`(또는 NSPanel), A = `.nonactivatingPanel` + 키 창 가능, C = `.nonactivatingPanel` + 키 창 불가. 켤 때 스위치를 읽어 창을 다시 만들고, 끌 때까지 고정한다.

## 시험 중 드러난 것

- **판을 다시 만들 때 캐시가 남던 누수** (시험판부터 있던 것): 옛 판을 `orderOut`만 해서 모니터 구성이 바뀔 때마다 화면 크기 캐시가 쌓였다. 이제 닫고 캐시를 직접 버린다(`InkView.releaseCache`).
  - 남은 문제: 앞서 키 창이던 옛 `InkView` 객체 자체는 닫고 떼어 내도 무언가가 붙들고 있다(첫 응답자 해제·풀 비우기로도 안 풀림). 캐시는 버리므로 메모리 걱정은 작다. S3a에서 다시 보거나, S5 모니터 작업 때 Instruments로 확인.
- C안에서는 판이 키 창이 아니라 `flagsChanged`가 오지 않는다. 드래그 도중 ⇧를 누르면 다음 마우스 움직임에서 방향 맞춤이 따라온다(움직이지 않으면 그대로).
- C안 드로잉 중에는 Esc도 우리가 잡으므로 ⌘⇧5 도구 막대를 Esc로 닫으려 하면 드로잉이 먼저 꺼진다(확인 목록 13번 d).
- 자체 점검 장면이 25개가 되었고 `build.sh --test`가 OK/FAIL 줄을 센다(S2a가 그림 비교를 더한다).
