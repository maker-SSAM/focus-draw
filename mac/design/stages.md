## 공통 규칙 (모든 세션)

- **고치는 범위**: 맥 세션은 `mac/**`과 그 단계가 이름을 댄 파일만 고친다. `focus-draw.ahk`·`NOTES.md`는 읽기만, 그것도 `grep -n 이름` 다음 앞뒤 40줄만 읽는다.
- **커밋**
  - 경로를 하나씩 적어 `git add`한다. `add -A`·`add .`는 쓰지 않는다.
  - 커밋 전에 `git status`, 커밋 후에 `git show --stat`으로 확인한다.
  - 메시지는 영어 명령형, 사용자가 보는 변화를 말로 쓰고 접두어는 붙이지 않는다. 끝에 Co-Authored-By 줄을 단다.
- **줄바꿈과 인코딩**
  - `.git/config`에 `core.autocrlf`를 **절대 설정하지 않는다.** OneDrive로 Windows와 공유되어 Windows 쪽 CRLF 규칙을 깬다.
  - 한글 텍스트를 perl로 고치지 않는다.
- **금지 API**
  - 권한이 필요한 API는 쓰지 않는다: 손쉬운 사용, 입력 모니터링, 화면 기록, `CGEventPost`, 이벤트 탭.
  - `SMAppService`는 `--selftest`·`--diag`·`--bench`·개발 실행에서 **호출하지 않는다.** 호출한 복사본으로 로그인 항목이 옮겨 가기 때문이다.
- **한글로 알리기**: 진행 과정의 질문과 진행 정보(지금 하는 일, 찾은 것, 선생님께 묻는 것)는 모두 한글로 쓴다. 커밋 메시지만 영어(2026-09-29 선생님 요청).
- **세션 끝**: ROADMAP의 "진행 기록"에 한 줄을 남기고 "다음 세션" 칸을 고친다. 설계를 결정했으면 `mac/design/`에 메모로 남긴다.
- **막히면**: 같은 증상을 두 번 고쳐도 안 되면 멈춘다. 증상·기록·실패한 점검을 적어 두고 Opus 세션으로 넘긴다.

### S1a · Sonnet · 기본 · 약 1시간

**git 안전** (결정 1·2·3에 답을 받은 뒤)
- `git config core.precomposeunicode true`만 설정한다. 확인할 것:
  - 한글 이름이 분해형(NFD)으로 중복되어 보이던 항목이 사라지는지: `읽어주세요.txt`, `터치펜-확인.ahk`, `소개자료/`, `배포용/`, `터치펜-확인-결과.txt`
  - `.gitignore`가 다시 맞는지
- 줄바꿈만 다른 Windows 파일 3개는 커밋도 되돌리기도 하지 않는다. `git ls-files --eol`로 "줄바꿈만 다름"을 확인해 기록한다.
- 다음 두 가지는 Windows 쪽 작업이라 그대로 둔다:
  - `github-social-preview.png` → `00-썸네일.png` 이름 변경
  - 추적하지 않는 `강의용 마우스 프로그램(…).txt`
- 결정 2는 "OneDrive 폴더 유지"다(사용자 결정). ROADMAP의 "OneDrive에서 작업할 때" 규칙을 CLAUDE.md에 옮겨 적는다. `git status`에 충돌 사본(`…-컴퓨터이름`, `index` 관련 파일)이 보이면 멈추고 알린다.

**세션 규칙 파일**
- 루트에 `CLAUDE.md`를 60줄 이하로 만든다. 위 "공통 규칙", 빌드·점검 명령, 인코딩 규칙(`읽어주세요.txt`·`.ps1`은 UTF-8 BOM+CRLF, Windows 세션에서만 고침)을 담는다.
- `mac/HISTORY.md`를 만들고 계획 v1 요약을 옮긴다.

**수업 중 멈춤 버그 수정**
- **H1 무지개·레이저 펜 도중 키 입력으로 앱 종료** (`Draw.swift:60-66`, `536-541`, `593`)
  - 원인: 긋는 도중 펜이 바뀌면 `hues` 개수가 점 개수보다 적어져 배열 범위를 넘는다.
  - 고치는 법: 마우스를 누를 때 "획 세션"(도구·색·굵기·진하기·도형)을 고정한다. 도중에 누른 키는 **다음 획**부터 적용한다. Shift 방향 맞춤만은 도중에도 따른다.
  - 색상 번호는 범위를 넘지 않게 막는다.
  - 펜을 바꾸면 `laserLive`를 끝내 60Hz 타이머가 멈추게 한다.
- **H2 숨긴 위젯이 되살아남** (`main.swift:29`): 드로잉을 켜고 꺼도 사용자가 숨긴 위젯은 보이지 않게 한다.
- **H4 반투명 획 확정 비용**: 투명층(`beginTransparencyLayer`)을 항목의 범위로 잘라서 만든다.
- **L1** ⌘Z·⌃Z는 드로잉 중에만 실행 취소로 쓴다. ⌘⇧Z는 실행 취소가 아니다.
- **제자리 오른쪽 클릭·⌥ 클릭**(트랙패드 두 손가락 탭 포함)은 아무것도 지우지 않고 실행 취소 단계도 만들지 않는다. 아무것도 바꾸지 않은 단계는 실행 취소 기록에서 건너뛴다.
- **종료할 때**(`applicationWillTerminate`): 그린 것은 둔 채 드로잉을 끄고, 판을 닫고, 커서를 보이게 하고, 단축키를 해제한다.
- 자체 점검에 장면을 추가한다:
  - 무지개·레이저·도형을 긋는 도중 숫자·A·S 입력 → 종료되지 않음, 색 개수 = 점 개수, "레이저 타이머 멈춤"
  - 숨긴 위젯이 드로잉을 두 번 켜고 꺼도 숨어 있음
  - 제자리 오른쪽 클릭 → 변화 없음
- 빌드 → 경로를 지정해 커밋 → 로컬 태그 `mac-v0.1.1`, zip 보관.

### S1b · Opus · 높음 · 약 1.5시간 (선생님 실습 전에 끝냄)

**진단 기록 `--diag`** (메뉴 항목으로도 둔다)
- 기록 위치: `~/Library/Logs/Focus & Draw/diag.log`
- 기록 내용:
  - macOS 버전, 맥 모델
  - 화면마다: UUID, 위치, 배율, 미러/확장, "디스플레이마다 별도 Spaces" 여부
  - 드로잉 중 1초마다: 우리 창의 화면 표시 여부·레벨·위치(`CGWindowListCopyWindowInfo` — 화면 기록 권한 불필요), 앞 앱, 키 창, 활성화 이벤트, 받은 키 코드(코드만), 커서 모드
  - 단축키 등록 결과(OSStatus), 화면 변경, 잠자기·깨어남

**시험용 스위치** (`Experiments.swift`, 개발 빌드의 숨은 "실험" 메뉴 — 선생님은 터미널을 쓸 필요 없음)
- **C안 (1순위 가설, Windows NOACTIVATE 방식)**
  - 판은 **키 창이 되지 않는** 비활성 패널로 둔다.
  - 드로잉 키를 **드로잉 중에만** Carbon 단축키로 등록한다: 1~0, QWER, A·S, Z·X·C(누름·뗌, ⇧ 조합 포함), +·−·=·키패드, delete·앞으로 지우기, Esc, ⌘Z, ⌃Z.
  - 나머지 키(→, PageDown, 리모컨, B)는 발표 앱으로 그대로 간다.
  - 마우스 이동은 `.activeAlways` 추적 영역으로 받는다.
  - 붓 동그라미는 판 위에 직접 그리고, 시스템 커서는 비공개 `SetsCursorInBackground` + `CGDisplayHideCursor`로 숨긴다.
- **B안**: 지금처럼 앱을 활성화한다. 돌려줄 때는 macOS 14 이상에서 `yieldActivation(to:)` + `activate(from:)`를 쓴다.
- **A안**: 비활성 패널이 키 창이 되게 한다.
- **창 동작 조합**: 지금 조합 / `.stationary` 뺀 것 / `.canJoinAllApplications`, 그리고 `NSWindow`와 `NSPanel` 비교.
- **커서**: 붓 커서를 `NSCursor`로 할지 판에 그릴지, 강조 중 커서 숨기기(비공개 API) 켬·끔.
- **C안에서 확인할 것**
  - +를 누르고 있으면 반복되는가 (안 되면 누름~뗌 사이 자체 반복 타이머)
  - 한글 입력 상태와 보안 입력(암호 칸)에서도 키가 들어오는가
  - 드로잉을 끌 때 단축키 해제가 반드시 일어나는가. 끄는 순간 확인하고, 감시 줄을 기록에 남긴다.
  - 해제가 안 되면 시스템 전체에서 글자 입력이 막힌다.

**속도 측정 `--bench`** (화면 없이, Claude가 실습 전에 직접 돌린다)
- 50% 형광펜 3,000점 획을 3024×1964와 5120×2880에서 측정한다: 이벤트당 ms(p50/p95), 지금 방식(H4 적용 후)과 "긋는 획 전용 그림" 방식 비교

- 5K 화면당 메모리
- 쉬는 동안 타이머 깨어남 횟수

  - 서명한 뒤에는 손대지 않는다.
- 점검을 추가한다: 모든 키의 스키마 왕복, Windows 고정 파일 일치, 단축키 표기 왕복(F9, ^!1, +F8, #!h), 등록·해제 반복, 묶음 되돌리기.
- **(선택) Opus · 중간**: `git diff mac-v0.2.0..HEAD -- mac/`만 설계도에 비추어 검토한다. 나온 문제는 인수인계에 적고 짧은 Sonnet 세션으로 고친다.

### 완료 조건

- 그리기 파일에 `Settings.shared`가 없다(grep). 400줄을 크게 넘는 파일이 없다.

## S4 교실에서 드로잉: 키·창·커서

**목표**: 키노트·파워포인트·PDF·브라우저 전체 화면 위에서 쇼를 끄지 않고 그려지고, 키와 커서가 SPIKES 결정대로 동작한다.
- 드로잉 중에는 드로잉 키만 쓰이고 **나머지 일반 키는 막힌다**(선생님 결정 ①). 끄는 즉시 모두 풀린다.
- 다른 앱·데스크톱으로 넘어가거나 잠자기·잠금이면 **Esc처럼 꺼진다**(결정 ②, D7).
- 붓 동그라미가 선 굵기와 정확히 같고, ⌥만 눌러도 지우개 링이 보인다.
- "보이는데 안 눌리는 창"이 없다.

**모델**: Sonnet · 기본(어려우면 높음). 막히면 Opus 규칙을 따른다. 설계도 [architecture.md](architecture.md) 3~6절을 먼저 읽는다.

### 할 일
- **키 (D2 · 결정 ①)** — 설계도 4절
  - `KeyMap.blockKeys`를 만든다: 글자·숫자·기호·스페이스·return·tab·화살표·PageUp/Down·Home/End·키패드·F1~F12(`app` 묶음 제외) × {없음, ⇧, ⌥, ⌥⇧} − `draw` 묶음. ⌘·⌃ 조합은 넣지 않는다.
  - 켤 때 `draw` → `block` 순서로 등록, 끌 때 둘 다 해제하고 남은 등록 0을 확인한다. `STRAY` 감시를 두 묶음에 건다.
  - 켜는 시간을 기록에 남긴다(`HK groups on ms=`). 100ms를 넘으면 기록에 적고 Opus에 넘긴다.
  - +/−는 자체 반복(0.45초 뒤 0.07초 간격)을 유지한다.
- **끄는 이유 (결정 ② · D7)** — 설계도 3절 표
  - `.appSwitch`: 드로잉 중 `NSWorkspace.didActivateApplicationNotification`이 우리 앱이 아닌 앱으로 오면 지우고 끈다.
  - `.spaceChange`: 드로잉 중 `activeSpaceDidChangeNotification`이면 지우고 끈다. 판을 따라 옮기던 `rebuildWindows(reason: "spaceChanged")`는 켜기 직전의 `ensureOnActiveSpace`만 남긴다.
  - `.sleep`·`.lock`: `willSleep`, `screensDidSleep`, `sessionDidResignActive`에서 지우고 끈다.
  - `.settings`: 설정 창을 열면 끄되 잉크는 남긴다.
  - 캡처(⌘⇧4·5) 중에는 꺼지지 않아야 한다(앞 앱이 바뀌지 않음 — SPIKES D2).
- **Esc**
  - 잉크와 칠판을 지우고 끈다. 앱을 활성화하지 않았으므로 두 번째 Esc는 그대로 쇼로 간다.
  - Esc의 반복·뗌이 뒤 앱으로 새지 않게 한다.
  - ⌘Z·⌃Z는 드로잉 중에만 실행 취소로 쓴다.
- **창과 레벨** — 설계도 5절
  - 창 동작은 지금 조합(`.canJoinAllSpaces .fullScreenAuxiliary .stationary .ignoresCycle`)을 판·강조·링·위젯에 쓴다(D1, R3·R4 차이 없음).
  - 드로잉 중에는 메뉴 막대와 Dock 자리까지 덮는다.
  - `CGShieldingWindowLevel`은 쓰지 않는다. 암호·Touch ID 창은 눌려야 한다.
  - 잉크는 캡처에 찍히게 둔다.
  - 위젯은 쉴 때 떠 있는 레벨, 드로잉 중에만 판 위로 올린다.
  - 켜고 끌 때마다 위젯을 다시 올린다. 손가락·펜 탭을 받도록 `acceptsFirstMouse`는 유지한다.
- **커서 (D3 · D5)** — 설계도 6절
  - 붓 동그라미는 선과 같은 크기로, 진하기 = 색별 진하기 × 전체 진하기로 한다.
  - 지우개 링(10단계까지)과 레이저 점은 판에 그린다(`BrushCursor`).
  - **⌥ 지우개 링**: `ModifierWatch`로 드로잉 중에만 ⌥ 상태를 읽는다(마우스 이동 때 + 20Hz). ⌥만 눌러도 링, 떼면 붓 동그라미. ⌥= 단축키가 오면 바로 링과 새 크기를 보인다(재시험 9번 의견).
  - 위젯이나 판 위 다른 창(⌘⇧4·⌘⇧5 화면, 시스템 창) 위에서는 화살표를 보인다. 이것은 **실제 포인터 아래 창**으로 판단하고, 저장해 둔 표시는 믿지 않는다.
  - 커서 갱신 주인은 하나로 한다.
  - `SystemCursor`: 호출 수를 세고, "숨김을 원하는데 `CGCursorIsVisible()==1`"이면 다시 숨긴다(앞 앱·데스크톱 바뀜, 마우스 이동 때 0.25초에 한 번까지). Dock을 지난 뒤 판 위로 돌아오면 다시 숨어야 한다.
- **설정 창**
  - 드로잉을 켜면 숨기고, 끄면 되살린다. 색 패널도 함께 숨긴다.
  - 설정을 열면 드로잉을 끄되 잉크는 남긴다.
- **점검 추가**
  - 켬·끔 상태별 키, Esc 두 번, ⌘Z 제한, 설정 숨김·복원, 영역별 커서 모드
  - 끈 뒤 `draw`·`block` 등록 남음 0, `block`에 ⌘·⌃ 조합 없음, 두 묶음에 겹치는 조합 없음
  - `OffReason`마다 잉크 남김·지움 (가짜 알림으로 앱 전환·데스크톱 전환·잠자기)
  - `SystemCursor` 호출 수 짝
  - 화면 표시 진단 줄
- PARITY를 갱신한다. **일부러 다름**: 드로잉 중 나머지 키 막기(①), 앱·데스크톱 전환 시 끄기(②), 잠자기 시 끄기. **불가능**: ⌘Tab 막기(대안: 넘어가면 끔).
- 맥용 안내문에 적을 것: 드로잉 중에는 슬라이드가 넘어가지 않음(Esc로 끄고 넘김), 쇼 중 메뉴는 위젯 오른쪽 클릭, 키노트 쇼는 스스로 화살표를 숨김(강조를 쓰면 자리가 보임).

### 완료 조건
- `--test`가 통과한다(커서 그림 변화는 선생님이 승인).
- 선생님 실행 기록에서 SPIKES가 "지원"이라 한 모든 발표 방식에서 판이 화면에 있다.
- 확인 목록이 전부 통과하거나, 실패한 것은 이유와 대안이 PARITY에 있다.

### 선생님 확인
1. 키노트 전체 화면: F9나 ⌃⌥2로 켜고 그린 뒤 → 나 리모컨을 누른다 → **슬라이드가 넘어가지 않는다**. Esc → 드로잉만 끝나고 쇼는 계속된다. → → 넘어간다. Esc 한 번 더 → 쇼가 끝난다. 파워포인트로 반복한다.

## S5 모니터 · 긴 수업 · 속도

**목표**: 프로젝터를 꽂고 빼거나 덮개를 닫거나 한 차시 내내 그려도 잉크가 사라지거나 움직이지 않는다. 레티나와 5K에서 긋기와 실행 취소가 빠르고, 쉬는 동안은 비용이 0이다. **실제 수업 한 차시**로 베타 1을 승인한다.

**모델**: Sonnet · 기본. 기준을 한 번 고쳐도 못 넘고 원인이 불분명하면 Opus(높음).

### 할 일
- **화면 (D6)**
  - 좌표는 주 화면 기준 전역 좌표를 유지한다.
  - "주 화면이 바뀜"과 "화면이 빠짐"을 명시적으로 처리하고, 어떻게 되는지 적는다.
  - 화면 변경 알림이 몰려 오면 한 번만 처리한다.
  - 긋는 도중 화면이 바뀌면 획을 깔끔히 끝낸다. 매달린 획이나 지우개가 남지 않아야 한다.
  - 위젯과 강조를 화면 안으로 다시 들인다.
  - 드로잉을 쓰기 전에는 화면별 그림을 만들지 않는다.
- **위젯**
  - 커서를 따라 다른 화면으로 넘어간다.
  - 저장한 자리가 화면 밖이면 기본 자리로 간다.
  - "처음 자리로"는 `NSScreen.screens.first`(주 화면)를 쓴다. `NSScreen.main`이 아니다.
- **그리기 (D4 결정 — 조건 없이 한다)** — 설계도 7절
  - `StrokeLayer`: 긋는 획은 전용 그림에 불투명하게 쌓고 층 진하기를 곱해 합친다. 갱신 범위는 새 토막 자리뿐, 이음매가 없어야 한다.
  - `FloorImage`: 30단계보다 오래된 항목은 화면별 바닥 그림에 굽는다. 실행 취소는 30개 이하만 다시 그리고, 그 화면에 걸친 것만 그린다.
  - 확정할 때마다 전체 그림을 복사하지 않는다. 바깥 진하기 층은 필요할 때만 쓴다.
  - 색 공간은 하나로 한다. 매번 sRGB→P3 변환을 하지 않는다.
  - `renderScene`은 기준 그림용 기준 경로로 남긴다. CALayer 교체는 하지 않는다.
  - `laserLive`를 정리하고, 그릴 것이 없으면 레이저 타이머를 멈춘다.
- **끈 뒤 (선생님 결정 ③)**
  - 끄는 순간 그림(`StrokeLayer`·`FloorImage`·판 버퍼)을 모두 버린다. 선 목록만 남긴다.
  - 다시 켤 때 남은 잉크(F9·설정으로 끈 경우)는 목록에서 한 번 다시 그린다. 2,000획에서 걸리는 시간을 재서 SPIKES D4에 적는다.
  - 끈 뒤 1분(`UNDO_KEEP_S=60`, 처음 10분)이 지나면 실행 취소 기록을 비우고, 화면이 비어 있으면 목록도 비운다. 끌 때 한 번 깨는 작업을 예약하고, 켤 때 취소한다. 켤 때 `expireIfNeeded`로 한 번 더 본다.
- **잠자기**: S4의 `.sleep`·`.lock`으로 꺼진다. 깨어난 뒤 앱 단축키(`app` 묶음)가 살아 있는지 확인하고 진단 한 줄을 남긴다. 강조·드로잉이 모두 꺼져 있을 때 도는 타이머가 없어야 한다.
- **점검 추가**
  - bench 기준을 단언으로 바꾼다: 5K 긋는 중 p95 ≤ 8ms, 2,000개 실행 취소 ≤ 50ms.
  - 5,000획 + 30번 취소 + 100번 켜고 끄기를 기준 시간 안에 한다.
  - 가짜 화면 목록 변경: 잉크 유지, 긋던 획 종료, 위젯 들임.
  - 가짜 시계로 1분 규칙(59초 되살림 O, 61초 X), 바닥 굽기를 넘나드는 전부 지우기 + 취소.
  - 끈 직후 그림 캐시 0, 쉬는 동안 타이머 0개.
- **학교 방문**: S1에 남은 학교 항목을 하고, 전자칠판 결과를 PARITY와 SPIKES D8에 적는다.

### 완료 조건
- `--test` 통과, bench 숫자가 SPIKES 기준 안에 든다.
- 진단 기록에서 드로잉을 끈 직후 메모리가 쉬는 값 근처로 돌아오고, 둘 다 끄면 타이머 0개다.
- 실제 수업 한 차시(키노트나 파워포인트 + 프로젝터)를 날짜·맥·macOS·커밋과 함께 기록했다.

### 선생님 확인
1. 가장 큰 화면에서 3 → 휠로 50% → 빠르고 긴 지그재그를 10초 → 끊김과 진한 이음매가 없다. S(무지개)로 반복한다.
2. 100획쯤 그린 뒤 ⌘Z 30번을 빠르게 → 매번 바로 취소된다.
3. 잉크를 띄운 채 프로젝터를 뽑았다 꽂기, 미러↔확장, 해상도 변경 → 맥북 화면의 잉크가 그 자리에 있다.
4. 프로젝터가 초점 화면일 때 "처음 자리로" → 위젯이 맥북 화면 오른쪽 아래로 간다.
5. 드로잉 중 덮개를 20초 닫았다 연다 → 드로잉이 꺼져 있다. ⌃⌥2로 켜고 ⌘Z → 선이 돌아온다. 2분 뒤에 같은 것을 하면 → 돌아오지 않는다.
6. 활동 모니터에서 둘 다 끔 → CPU 0.0%. 메모리 값을 적는다.
7. (학교) 전자칠판에서 터치로 그려지고, 위젯 탭이 되고, 길게 눌러도 지워지지 않는다.
8. 이 판으로 수업 한 차시를 하고 O/X 메모를 한 번에 보낸다 → 베타 1 승인.

## S6 드로잉 세부 맞추기

**목표**: Windows README의 드로잉 규칙이 맥에서 같게 동작하거나, 일부러 다르면 PARITY에 이유가 있다.

**모델**: Sonnet · 기본. Windows 세부는 `ArrowGeometry`, `DrawArrowGdip`, `ShowStepNumber`, `EraserRingColor`, `UndoDrawing`, `DrawPoll`을 grep해서 앞뒤 40줄만 읽는다.

### 할 일
- **화살표와 레이저**
  - 화살촉은 **채운 삼각형**으로 한다(Windows와 같음).
  - 무지개 화살촉은 몸통이 끝난 색으로 채운다.
  - 레이저 획마다 자기 색을 가진 채 사라진다.
- **굵기 숫자 표시**
  - macOS 도움말 풍선 모양으로 한다: 밝은 바탕, 얇은 회색 테, 반경 5, 진한 글자.
  - 커서 중심에서 오른쪽 아래 22pt에 띄우고, 화면 가장자리에서는 안쪽으로 뒤집는다.
  - 끝 단계에서도 뜨고, 0.5초 동안 보인다. 휠 진하기 %도 같은 모양이다.
- **지우개 링**
  - ⌥를 누르는 즉시 링이 보인다.
  - ⌥나 오른쪽 버튼 + +/−는 지우개 크기를, 그 밖의 +/−는 펜 굵기를 바꾼다.
- **휠**
  - 마우스는 "자연스러운 스크롤" 설정과 관계없이 위로 굴리면 진해진다(`isDirectionInvertedFromDevice`).
  - 관성 스크롤은 무시한다.
  - 트랙패드 방향은 결정 7을 따른다.
- **제자리 클릭**은 결정 6을 따라 코드와 PARITY를 맞춘다. README는 S12에서 고친다.
- **오른쪽 버튼**
  - 왼쪽 획 도중에는 오른쪽 끌기를 시작하지 않는다.
  - 획 도중 오른쪽 버튼을 눌러도 흔적이 남지 않는다.
  - 마지막 뗀 점까지 획에 넣는다.
- **(선택, 와콤·Sidecar가 있을 때만)**
  - 펜 뒤쪽 지우개는 근접 이벤트에서 `pointingDeviceType == .eraser`일 때 1배로 지운다. 닿는 순간 한 번 정하고 획 끝까지 유지한다.
  - 태블릿만 이벤트 합치기를 끈다.
  - 필압은 Windows에 없으므로 선생님이 원할 때만 한다.
- 바뀐 기준 그림(화살촉, 무지개 촉, 레이저 꼬리, 숫자 표시)은 한 번에 모아 승인받는다. 규칙마다 단언을 추가한다.

### 완료 조건
- 기준 그림 요약에 위 장면만 바뀌었고 승인되었다. 새 단언이 통과한다.
- PARITY 드로잉 절의 모든 줄이 "완료" 또는 "일부러 다름+이유"다.

### 선생님 확인
1. C 끌기 → 화살촉이 채워져 있다. S → C 끌기 → 촉이 몸통 끝 색이다.
2. A로 긋고 꼬리가 사라지는 동안 5 → 꼬리는 빨강 그대로다.
3. 오른쪽·아래 가장자리 근처에서 + → 도움말 모양 숫자가 안쪽으로 뒤집혀 뜬다.
4. ⌥만 누름 → 링이 보인다. ⌥ + '+' → 링이 커진다.
5. 자연스러운 스크롤을 켠 마우스로 휠 위 → 진해진다. 트랙패드도 자연스럽고, 튕긴 뒤 손을 떼면 멈춘다.
6. 움직이지 않은 한 번 클릭 → 결정 6대로다.
7. 왼쪽 획 도중 오른쪽 버튼 → 흔적이 없다.
8. (태블릿이 있으면) 펜을 뒤집으면 지우개가 된다.

## S8 설정 창 · 단축키

**목표**: 맥 설정 창이 Windows 설정 창의 모든 것을 같은 저장·초기화 규칙으로 제공한다. 두 전역 단축키를 안전하게 바꿀 수 있고, 키보드 그림은 늘 지금 키와 색을 보여 준다.

**모델**: Sonnet · 기본, 새 세션 두 개. 등록기가 설명할 수 없게 틀어지면 Opus(높음).

### S8a 설정 탭
- **창 구성**
  - 탭은 일반·포커스·드로잉·위젯·단축키 5개.
  - 아래 버튼: 프로그램 종료(떨어뜨리고 흐리게), 저장, 닫기.
  - 늘 위에 두지 않는다. 닫으면 앞 앱으로 초점을 돌려준다.
- **숫자 칸**
  - 슬라이더, −/+, 숫자 입력(Enter나 칸을 떠날 때 적용) 중 무엇으로든 바꾼다. 스키마 범위로 자른다.
  - 슬라이더 간격은 크기·진하기 5, 위젯 크기 10이다. 직접 입력한 숫자는 간격을 따르지 않는다.
- **포커스 탭**
  - 테두리 상자 셋: 포커스 하이라이트, 클릭효과(좌), 클릭효과(우).
  - 켬·끔은 상자 제목에 두고, 끄면 내용을 흐리게 한다.
  - 커서 숨기기 칸은 D5대로 둔다(연결은 S9).
- **드로잉 탭**
  - 기본색, 굵기 1~10, 진하기, 지우개 1~10.
  - 1~9와 W/E/R 12줄은 스크롤 목록으로, 색과 진하기 5~100%를 둔다.
  - "전체 진하기는 색별 진하기에 곱해진다"는 설명을 단다.
- **위젯 탭**: 크기 60~250, 색, 진하기 20~100, 보이기, 처음 자리로 되돌리기.
- **일반 탭**
  - 로그인 시 자동 실행(`SMAppService.mainApp`)
    - 누르는 즉시 적용하고, `.status`를 매번 읽는다.
    - 임시 위치에서 실행 중이거나 응용 프로그램 폴더 밖이면 안내하고 거절한다.
    - `.requiresApproval`이면 시스템 설정 › 일반 › 로그인 항목을 안내한다.
  - 모든 설정 초기화
    - 기본 선택이 "아니요"인 확인 창을 띄운다.
    - ini를 지우고 다시 읽은 뒤, 단축키를 재등록하고 위젯을 처음 자리로 보낸다. 로그인 항목은 그대로 둔다.
    - 파일을 지울 수 없으면 설명한다.
  - 버전(Info.plist), 제작자, MIT.
  - 설정 폴더 열기: 다른 맥으로 설정을 옮기는 방법이기도 하다.
- **색과 편집 단축키**
  - 색 선택은 자체 상태를 둔다. 8비트 왕복 때문에 색이 튀지 않게 하려는 것이다.
  - 색 패널은 설정과 함께 닫히고, 판 아래에 깔리지 않는다.
  - 메인 메뉴에 편집 메뉴를 넣어 ⌘C/⌘V/⌘X/⌘A/⌘W가 되게 한다.

### S8b 단축키와 키보드 그림
- **녹화 칸**
  - 칸에 초점이 있을 때만 키를 지켜본다.
  - ⌃⌥⇧⌘ 기호로 보인다. 입력 글자가 아니라 키 코드로 이름을 붙여서 한글 입력과 무관하다.
  - 보조 키만 누른 상태는 무시하고, 다시 들어옴을 막는다.
  - 등록부로 즉시 다시 등록한다. 줄마다 "기본값" 버튼을 둔다.
  - 저장하면 `[Hotkeys]`에 AHK 표기로 남는다.
- **거절 규칙**
  - 글자·숫자는 ⌃가 있거나, ⌘와 ⌃·⌥ 중 하나가 함께 있어야 한다.
  - ⌥·⌥⇧만으로는 거절한다. 글자를 입력하고, macOS 15.0~15.1이 -9868로 거절하기 때문이다.
  - ⌘+글자만으로는 거절한다(앱 단축키와 겹침).
  - F1~F19는 단독도 허용하고 맥북 fn 안내를 붙인다.
  - 다음도 거절한다: ⌘Space, ⌃Space(입력 소스), ⌘Tab, ⌃←/→/↑, ⌘⇧3/4/5, 다른 기능이 쓰는 조합, 등록 오류(-9878은 다른 앱이 사용 중).
  - 거절할 때마다 한국어로 이유를 말하고 원래 키로 돌린다.
  - 드로잉 키(⌘Z, ⌥ 끌기, delete 포함)는 바꿀 수 없다.
- **메뉴와 키보드 그림**
  - 메뉴 막대 항목에 지금 단축키를 보인다.
  - "드로잉 모드 단축키 보기"는 `KeyMap`으로 만든 **SwiftUI 키보드 화면**이다.
    - 맥 자판 줄마다 역할을 적는다: 숫자 줄 = 색, Q 줄 = 칠판, A 줄 = 특수 펜, Z 줄 = 도형, 그리고 ⌘Z·delete·⌥ 끌기·+/−.
    - 지금 색 13가지를 함께 보인다.
    - Esc나 클릭으로 닫는다. 화면에 맞추되 원래보다 키우지 않는다.
  - 자체 점검이 문서용 PNG를 뽑는다.
- **점검 추가**
  - 탭 그림, 사용자에게 보이는 모든 스키마 키에 범위가 맞는 칸이 있는지
  - 읽기 전용 폴더에서 저장 실패 → 안내 창(절대 "저장됨"이 아님)
  - 임시 폴더에서 모두 초기화
  - 조합 20개를 규칙에 넣어 허용·거절과 이유 확인
  - Windows 표기 왕복
  - 점검·진단·측정·개발 실행에서 `SMAppService` 호출 0

### 완료 조건
- `--test`가 탭·키보드 그림과 스키마 범위·저장 실패·초기화·단축키 규칙 단언과 함께 통과한다.
- Windows README "세부 설정" 절의 모든 항목이 맥에 있거나, PARITY에 이유가 있다.
- 모두 초기화 앞뒤로 로그인 항목 상태가 같다.

### 선생님 확인
1. 탭마다 값 하나를 슬라이더·−/+·입력+Enter로 바꾼다. 저장 → "저장됨", 다시 열면 → 유지된다. 저장하지 않고 닫으면 → 종료 전까지만 유지된다.
2. 3번을 노랑 40%로 → 형광펜이 된다. W 칠판 70% → 자료가 희미하게 비친다.
3. 응용 프로그램 폴더에서 로그인 시 실행을 켠다 → 로그인 항목에 보인다. 로그아웃 후 로그인 → 앱이 켜진다.
4. 모두 초기화 → 먼저 묻고 기본 선택은 "아니요"다. 예 → 모두 기본값이 되고 로그인 항목은 그대로다.
5. 숫자 칸에서 ⌘V가 되고, ⌘W로 설정이 닫히며 색 패널도 함께 닫힌다.
6. 설정 폴더를 읽기 전용으로 두고 저장 → 한국어 설명이 나오고 "저장됨"은 안 나온다. 끝나면 되돌린다.
7. 강조를 ⌃⌥H로 → 바로 된다. 저장 후 다시 열어도 ⌃⌥H다.
8. H, ⌥H, ⌘H, ⌘Space, ⌃Space, 드로잉 키를 시도 → 모두 이유와 함께 거절되고 원래 키로 돌아온다.

## S9 강조 · 위젯 · 메뉴 막대 마무리

**목표**: 강조와 위젯이 Windows만큼 자연스럽고 가볍다. 선생님이 Windows에서 쓰는 커서 숨기기(HideCursor=1)도 맥에서 쓸 수 있다. 쉬는 동안 비용은 0이다.

**모델**: Sonnet · 기본. D5의 비공개 커서 경로가 이상하면(예: Tahoe 전체 화면 메뉴 막대 뒤) Opus(높음).

### 할 일
- **강조 중 커서 숨기기 (D5)**
  - 강조 창 안에 32×32 십자선(팔 2px, 두께 1px)을 그린다.
  - D5 결정: 비공개 숨김 경로를 **제공**한다. S4의 `SystemCursor` 다시 숨기기를 강조에도 쓴다: 앞 앱이 바뀐 뒤·데스크톱을 바꾼 뒤·Dock을 떠난 뒤 다시 숨어야 한다(재시험 14번에서는 강조를 다시 켜야 숨었다).
  - Dock 위에서는 화살표가 보인다(시스템 한계).
  - 종료·잠자기·드로잉 전환 때는 복구한다.
  - 기본값은 결정 10(추천: 켬).
- **강조 따라가기**
  - 전역·로컬 마우스 이동 감시로 따라간다. 움직일 때만 디스플레이 링크를 쓴다.
  - 늘 도는 120Hz 타이머를 없애고, 지연도 없어야 한다.
  - 전체 화면과 모든 Space 위에 뜬다(S4의 창 동작).
- **클릭 링**
  - Windows 식을 쓴다: ease-out cubic 30프레임, 간격 41−빠르기 ms, 시작 반지름 = 크기/2 − 굵기/2 − 1.
  - 트랙패드 보조 클릭과 ⌃클릭에도 오른쪽 링을 보일지 정한다. 기본은 "오른쪽 클릭과 같음".
- **위젯 끌기**
  - Dock 가장자리에 15pt 안에서 자석으로 붙는다(아래·왼쪽·오른쪽 Dock). 더 끌면 지나간다.

  - 자리는 "커서 − 잡은 거리"로 정하고, 벽에서는 잡은 거리를 다시 잡아 누적이 없게 한다.
  - 메뉴 막대·노치 아래로는 못 가지만 Dock 위에는 둘 수 있다.
- **위젯 세부**
  - 켤 때 (0,0)에서 깜박이지 않는다.
  - 크기를 바꾼 뒤 그림자를 새로 그린다.
  - 아이콘 색은 화면 배율마다 입힌다.
  - 버튼에 VoiceOver 이름을 단다.
- **(선택)** 강조·드로잉 전용 메뉴 막대 아이콘(`ShowTrayIcons`)
  - 기본은 끔이다. 한 번 누르면 켜고 끄며, 켜져 있으면 파랑(0A84FF)이다.
  - 주 아이콘은 밝게·어둡게 모드를 따르고 늘 남는다.
- **(선택, 맥 추가)** 드로잉 중 위젯에 실행 취소·전부 지우기 버튼을 둔다. 기본은 끔이다. 칠판 앞에서 키보드 없이 쓰기 위한 것이다.
- **점검 추가**
  - 자석 계산표: 아래·왼쪽·오른쪽 Dock, 자동 숨김, 14·15·16pt
  - 위젯 기준 그림: 60·100·250%, 20%
  - 링 프레임, 쉬는 타이머 0
  - 가짜 두 번째 화면에서 주 화면 기본 자리

### 완료 조건

- PARITY 포커스·위젯 절이 모두 "완료" 또는 "일부러 다름+대안"이다.

### 선생님 확인
1. 강조를 켜고 커서 숨기기 켬 → 키노트·사파리·Finder 위에서 숨는다. Dock 위에서는 화살표가 보이고(시스템 한계), **Dock을 떠나면 다시 숨는다**. 네 손가락으로 데스크톱을 바꾸거나 ⌘Tab 뒤에도 숨어 있다. 종료하면 정상 화살표다.
2. 마우스를 빠르게 돌린다 → 강조가 따라온다. 멈추면 → CPU가 0%에 가깝다.
3. 전체 화면 쇼와 다른 Space에서도 강조가 보인다.
4. 위젯을 Dock 쪽으로 → 15pt쯤에서 붙는다. 더 끌면 → Dock 위에 놓인다. Dock 왼쪽·오른쪽·자동 숨김으로 반복한다.
5. 위젯을 위로 → 메뉴 막대와 노치 아래에서 멈춘다. 화면 가장자리에는 자석이 없다.
6. 켤 때 모서리 깜박임이 없다. 60·100·250%, 20%가 제대로 보인다.
7. (켰다면) 전용 아이콘 한 번 → 켜고 끄며, 켜진 동안 파랗다.
8. (만들었다면) 드로잉 중 위젯의 취소·지우기 버튼이 손가락으로도 된다.
9. 오른쪽 링을 켜고 트랙패드 보조 클릭 → 정한 대로 동작한다.

## S10 Apple 서명 · 공증 (선택, 유료)

**목표**: 모든 동료와 모든 업데이트에서 "그래도 열기"와 관리자 암호 단계를 없앤다. 시점은 S7의 결정을 따르고, 기본은 베타 2 직전이다. 그래야 베타 2가 서명된 첫 실행을 시험한다.

### 선생님 확인
1. 가입, 인증서, `store-credentials`를 직접 한다(Claude는 순서만 안내).
2. 두 번째 계정이나 가상 맥에서 사파리로 서명된 zip을 받아 연다 → 보통의 "인터넷에서 받은 앱" 안내만 나온다. 그래도 열기와 관리자 암호가 없다.

## 옮기지 않는 것 (이유와 대안)

| Windows 기능 | 이유 | 맥에서는 |
|---|---|---|
| F8/F9가 앞 앱에도 전달됨 | Carbon 단축키는 키를 먹는다. 전달하려면 권한이 필요하고, 서명 없는 앱은 업데이트마다 권한이 풀린다 | PARITY "일부러 다름", 단축키 바꾸기(S8) |
| 손날(넓은 접촉) 지우개, 2배 폭, 접촉 크기 기준값 | 맥은 터치 칠판을 마우스 한 점으로 받아 접촉 크기가 없다(서드파티 드라이버 제외) | 오른쪽 끌기, ⌥ 끌기, delete, ⌘Z, (선택) 위젯 버튼 |
| 두 손가락 톡 실행 취소 (칠판) | 멀티터치가 오지 않는다 | ⌘Z, (선택) 위젯 버튼 |
| 터치펜-확인 도구 | 잴 접촉 크기가 없다 | `--diag`가 칠판이 보내는 이벤트 종류를 기록 |
| 예전 공용 색 설정 옮기기 | 맥에는 예전 설정이 없다 | — |
| 앱 옆 settings.ini(휴대) | 맥 앱 폴더는 읽기 전용·임시 위치가 잦다 | "설정 폴더 열기" + 같은 파일 형식(S8). 요청이 있으면 내보내기·가져오기 |
| HTML로 만든 단축키 PNG | Claude가 HTML을 찍을 수 없고, 살아 있는 화면이 늘 지금 색을 보여 준다 | SwiftUI 키보드 화면(S8) |
| 소스 다시 읽기(Ctrl+Alt+R) | 컴파일된 Swift | `build.sh --run` |
| 충돌 뒤 숨은 커서 복구 | 프로세스가 끝나면 macOS가 커서를 되돌린다 | 종료할 때 보이기만(S1a) |
| 붓 커서 대비 테두리 | 선생님이 Windows에서 이미 거절함(테두리·최소 크기·진하기 하한) | "다른 숫자키" 안내만(S12) |

**하지 않는 것**
- 영어 번역
- 필압 굵기: Windows에 없으므로 요청이 있을 때만.
- 화면 캡처에서 판 숨기기: macOS 15 이상에서 불가능하고 원하지도 않는다.
- Homebrew: Gatekeeper를 통과하지 못하는 앱은 받지 않는다.
- 접근성 권한으로 리모컨 키 전달: C안이라 필요 없다. 드로잉 중에는 선생님 결정 ①로 일부러 막는다(끄면 그대로 넘어감).
- ⌘Tab 막기: 우리 앱이 앞으로 나와야 해서 키노트 쇼가 꺼진다. 대신 넘어가면 드로잉을 끈다(결정 ②).
- 맥 버전 번호를 Windows와 맞추기: 독립 태그를 쓴다.
- 트랙패드 실행 취소 제스처와 동작 줄이기용 클릭 링: 두 손가락 탭이 이미 오른쪽 클릭(지우개)이라, 테스터가 원할 때 Opus 설계부터 한다.
