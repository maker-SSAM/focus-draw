## 0. 집 시험은 모두 B안으로 돌았다

- 진단 기록에 `MARK 항목 N`이 한 줄도 없다(마지막 `MARK 실험 끝`만). 드로잉을 켠 59번이 모두 `key=B inkWindow=NSWindow cursor=system spotHide=0`.

- 그래서 checklist.md의 "C안" 제목 결과(1~5, 9~11, 13~14)는 **B안 결과**로 읽는다. A안·창 동작 비교·판 커서·커서 숨기기는 아직 시험하지 않았다.
- 막는 장치(적용): 개발용 빌드는 드로잉을 켤 때 커서 옆에 `R1 · C안`처럼 지금 안을 2초 보여 준다. 재시험 목록은 항목 고르기를 준비 ⭐로 두고 이 표시로 확인하게 했다.

**C안 쪽 단서**: 00:45:46 화면 알림 폭주 때 판이 새로 만들어져 떴을 때, 키노트가 앞 앱인 채(`front=Keynote active=0`) 판이 맨 위에서(`above=[]`) 2초 동안 마우스 이동 308번을 받았다(00:45:47~48). 곧 선생님이 클릭하자 B안 판이 앱을 앞으로 불렀다(00:45:48). "앱을 부르지 않는 판이 발표 앱 위에서 마우스를 받는다"는 C안의 전제는 성립할 가능성이 높다.

**새 버그 ① 전체 화면 데스크톱에서 판·강조가 안 뜸 — 고침**
- 증상: 한 번 숨긴(orderOut) 창은 숨긴 데스크톱에 묶인다. 그 전부터 있던 다른 앱의 전체 화면 데스크톱에서 다시 띄우면 `on=0 space=0`이다. 데스크톱이 바뀔 때 판이 같이 밀려나는 좌표(`-346`, `-637`)도 찍혔다. 반대로 새로 만든 창(알림 폭주 때 만든 판 #17882·#19913)은 지금 데스크톱에 떴다.
- 강조 원·클릭 링·위젯도 "만들어 두고 숨겼다 띄우는" 같은 방식이다. 11번의 "강조가 가상 데스크톱을 벗어나면 안 됨"과 맞다.
- 고침: 띄우기 직전과 데스크톱이 바뀐 직후에 `isOnActiveSpace`를 보고(`isOffActiveSpace`, Spotlight.swift), 아니면 새로 만든다. 판(`DRAW rebuilt reason=offSpace·spaceChanged`), 강조 원·클릭 링(`SPOT rebuilt`), 위젯(`WIDGET rebuilt`). 1초 표본에 `spot=[on space]`·`widget=[on space]`를 더했다.
- 확인: 재시험 5번(사파리 전체 화면에서 처음부터 뜨는가).

**새 버그 ② 화면 알림 폭주 — 고침**
- 키노트 쇼가 시작하거나 끝날 때 화면 구성은 그대로인데 "화면 설정 바뀜" 알림이 1~2초에 수십~190번 왔다(모두 2,504번, 기록 5,009줄). 앱은 그때마다 판을 새로 만들었다(판 창 번호 31개).
- 원인 추정: 쇼 전환 때 화면 밝기 여유(EDR)가 매 프레임 바뀐다. 다음 기록의 `SCREEN same … edr=`로 확인한다.
- 고침: 0.3초 모은 뒤 화면 구성(`screenSignature`: 번호·자리·크기·배율)이 다를 때만 새로 만든다. 진단 기록은 같은 알림을 `SCREEN same xN` 한 줄로 센다. 자체 점검에 "화면 알림 60번에도 판을 새로 만들지 않음"을 더했다.

**미리 정한 규칙의 적용**
- "키노트 전체 화면이 모든 안에서 실패하면 '재생 › 윈도우에서'를 안내" — B안만 실패했으므로 아직 적용하지 않는다. 재시험 1(C)·12(A)·13(C+창 동작)이 모두 실패하면 적용한다.
- "어떤 전체 화면에서도 안 되면 멈춤" — 해당 없음(파워포인트·PDF·브라우저는 뜬다).

## D2 키보드를 어떻게 받나 — 보류 (C안 1순위)

- B안의 문제는 계획보다 크다. 리모컨·→가 막힐 뿐 아니라 **키노트 쇼 자체가 꺼진다.** 맥 교사의 주 발표 앱이 키노트이므로 B안은 기본값이 될 수 없다.
- B안에서 확인된 것: 한글 입력 상태에서도 키 자리로 동작한다(`inputSource=…Korean…`에서 code=20 등). A·S를 길게 누르면 시스템 반복이 온다(`repeat`). ⌥=로 지우개 크기가 바뀐다(code=24 mods=⌥).
- 끈 뒤 글자(4번)·암호 칸(5번)은 B안이라, C안의 위험(단축키가 안 풀림, 보안 입력)은 아직 시험하지 못했다.
- 규칙(그대로): 재시험 1·2·3에서 리모컨·→가 넘어가고 드로잉 키(누르고 있는 Z/X/C, ⇧ 조합, + 반복, delete, Esc)가 한글에서도 되며, 4번이 세 번 모두 O면 **C안**. 1번 a·c가 X면 12번(A안)과 "윈도우에서 재생 안내"를 비교한다.
- 덧붙인 규칙: 8번(드로잉 중 ⌘Tab)에서 다른 앱에 글자가 안 쳐져도 C안을 떨어뜨리지 않는다. 드로잉을 켠 동안 글자 키를 잡아 두는 것은 Windows 판과 같은 동작이다. 안내문에 적는다.

## D3 붓 커서 — 결정: 판에 직접 그리고 시스템 커서를 숨긴다

- 근거: 11번 c. NSCursor로 만든 빨간 점과 지우개 링이 "포인터 크기" 설정을 따라 커진다. 실제 굵기와 다른 크기를 보여 주므로 규칙 "NSCursor가 포인터 크기에 따라 커지면 판에 직접 그린다"에 해당한다.
- 덧붙여 11번 a: NSCursor 방식은 켜자마자 화살표였다가 마우스를 움직여야 빨간 점으로 바뀐다.
- 남은 확인(재시험 9번): 판 커서가 켜자마자 보이는지, 가장 큰 지우개 링이 잘리지 않는지, 늦게 따라오지 않는지. 문제가 있으면 S4에서 고친다(결정은 그대로).
- 적용: S4. 판 위 그리기(`Cursor`) + 숨김 이유를 모아 짝을 맞추는 `SystemCursor`(이미 있음).

## D4 그리기 방식 — 결정: CoreGraphics 유지, 두 가지만 고친다

- 근거(bench, M4·15.7.3): 5K 넓게 칠하기의 긋는 중 p95가 31.3ms(기준 ≤ 8ms를 넘음)인데 "획 전용 그림"은 0.07ms. 실행 취소 2,000개가 274ms(기준 ≤ 50ms를 넘음)이고 항목 수에 비례한다(개당 약 0.13ms).
- 결정: ① 긋는 획은 전용 그림에 불투명하게 쌓고, 새 토막 자리만 진하기를 곱해 합친다. ② 실행 취소 30단계보다 오래된 항목은 바닥 그림에 굽고 30개만 다시 그린다(약 4ms).
- S5의 "CALayer로 교체"는 하지 않는다. 실제 창(IOSurface)에서 다시 재는 일은 S5에서 `--bench`로 한다.

## D5 강조 중 커서 숨기기 — 보류

- 첫 시험은 스위치가 꺼진 채였다(`spotHide=0`, `CURSOR` 기록 0줄). 12번 a의 "바탕화면·사파리에서 화살표 정상"은 끈 상태의 정상 동작이다.

## 설계도(architecture.md)로 넘길 규칙

1. **창은 띄울 때마다 지금 데스크톱에 있는지 확인**하고, 아니면 새로 만든다(판·강조 원·클릭 링·위젯). 판을 새로 만들 때 지금은 목록에서 다시 그린다. D4의 굽기가 들어오면 빨라진다.
2. **화면 알림은 모아서, 구성이 바뀔 때만** 새로 만든다.
3. **발표 앱을 앞에서 밀어내지 않는다.** 드로잉·메뉴·위젯 어느 것도 우리 앱을 앞으로 부르지 않는다(C안). 설정 창만 예외다. 열 때 드로잉을 끄고 "쇼가 꺼질 수 있음"을 안내한다.
4. 쇼 중 메뉴는 위젯 오른쪽 클릭으로 연다. 맥용 안내문에 적는다.
5. 판 커서는 판에 그린다(D3).
6. 그리기는 CoreGraphics + 획 전용 그림 + 굽기(D4).
