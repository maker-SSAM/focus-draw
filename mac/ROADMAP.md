### OneDrive에서 작업할 때 (결정 2)

`.git` 폴더까지 OneDrive로 Windows PC와 공유되므로 다음을 지킨다.

- **두 PC에서 동시에 작업하지 않는다.** 한쪽에서 git을 쓰기 전에 OneDrive 동기화가 끝났는지(초록 체크) 확인한다.
- 프로젝트 폴더는 Finder에서 **"항상 이 기기에 유지"**로 둔다. 파일이 "온라인 전용"으로 바뀌면 빌드와 git이 느려지거나 실패한다.
- `core.autocrlf`는 설정하지 않는다.
- 폴더 안에 `…-컴퓨터이름` 같은 **충돌 사본**이 생기면 그 세션에서 멈추고 선생님께 알린다.
- 빌드는 지금처럼 임시 폴더에서 조립한다(서명 문제 방지).

## 재점검에서 새로 알게 된 것 (계획을 바꾼 이유)

1. **슬라이드 넘기기가 막힌다.** 맥 시험판은 드로잉을 켜면 앱이 앞으로 나와 **모든 키**를 가져간다. 그래서 프레젠터 리모컨·화살표로 키노트를 넘길 수 없다. Windows 판은 드로잉 키만 가로채고 나머지는 발표 앱으로 보낸다.
   - 맥에서도 권한 없이 Windows처럼 만들 방법("C안")이 있다. 다만 실제 맥북에서 시험해 봐야 안다 → **S1에서 가장 먼저 확인한다.**
2. **수업 중 앱이 꺼질 수 있는 버그**가 있다.
   - 무지개 펜으로 긋는 도중 숫자키를 누르면 앱이 종료되고, 그린 것이 사라진다.
   - 숨긴 위젯이 드로잉을 켜고 끌 때마다 다시 나타난다.
   - → **S1a에서 바로 고친다.**
3. **설정 파일이 지워질 수 있다.**
   - Windows의 settings.ini는 UTF-16 형식이라 맥이 읽지 못하고, 위젯을 옮기는 순간 덮어쓴다.
   - 맥이 모르는 항목(`[Hotkeys]` 등)은 저장할 때 사라진다.
   - → S2b.
4. **git이 위험한 상태다.**
   - 한글 파일 이름이 맥에서 두 가지 형태로 보여 같은 파일이 두 번 있는 것처럼 나온다.
   - `.git` 폴더가 OneDrive로 Windows PC와 공유되고 있다. 맥에서 잘못 커밋하면 Windows 쪽 파일의 줄바꿈이 망가진다.
   - → S1a.
5. **배포가 Windows보다 번거롭다.**
   - macOS 15부터 서명 없는 앱은 "그래도 열기"를 누르고 **관리자 암호**까지 넣어야 한다. 새 버전을 받을 때마다 반복된다.
   - 학교가 관리하는 맥에서는 아예 못 열 수도 있다.
   - → 동료 알파(S2b)로 일찍 확인하고, S7에서 서명을 결정한다.
6. **전자칠판**: 맥은 터치 칠판을 "마우스 한 점"으로만 인식한다. 손날 지우개와 두 손가락 실행 취소는 맥에서 불가능하다 → 안내문에 솔직하게 적고, 위젯 버튼 등으로 대신한다.
7. **큰 화면 성능**: 반투명 펜의 획을 확정할 때 화면 전체 크기의 임시 그림을 만든다. 한 줄로 고칠 수 있다(S1a). 나머지는 S1b에서 **재 보고** 필요할 때만 크게 고친다.
8. **최신 macOS**: 조사 시점에 macOS 27이 나와 있다. 선생님 맥북은 15.7이라, 26·27에서의 동작은 동료 테스터와 GitHub 자동 점검으로 확인한다.

## 원칙

- **위험한 것부터**: 구조를 바꾸기 전에, 설계를 뒤집을 수 있는 질문(발표 화면 위에 뜨는가, 키가 어디로 가는가, 커서, 속도)을 실제 맥북에서 먼저 확인한다.
- **Windows 판이 기준**이다.
  - README는 필요한 절만, `focus-draw.ahk`·`NOTES.md`는 함수 이름으로 찾아 앞뒤 40줄 정도만 읽는다.
  - README와 코드가 다르면 선생님이 정한다.
- **권한을 묻지 않는 앱**: 서명 전에는 "손쉬운 사용"·"입력 모니터링"·"화면 기록" 권한이 필요한 기능을 쓰지 않는다. 서명 없는 앱은 업데이트할 때마다 권한이 풀리기 때문이다.
- **설정 파일은 Windows와 호환되게**, 모르는 항목도 지우지 않게 둔다. 설정 파일을 배포 파일에 넣지 않는다.
- **쉬는 동안 0**: 강조·드로잉이 모두 꺼져 있으면 도는 타이머가 없다.
- **고치기 전에 고정**: 그림 기준 자체 점검(골든 이미지)을 먼저 만든다. 구조 정리는 "그림이 하나도 안 바뀌었다"로 끝낸다.
- **눈은 자체 점검, 손은 선생님**: Claude는 스크린샷을 못 보므로 자동 점검으로 확인한다. 가짜 입력으로 못 보는 것은 단계마다 **선생님 확인 목록**(15개 이하, 예상 결과 포함)으로 넘긴다. 답은 "3번 X: 슬라이드가 안 넘어감"처럼 번호별 O/X 한 번에 보내면 된다.
- **두 판은 따로**:
  - 맥 세션은 `mac/` 안만 고친다. 두 판을 한 세션에서 고치지 않는다.
  - `읽어주세요.txt`는 Windows 세션에서만 고친다.
- **맥 릴리스는 독립**: `mac-v0.x` 태그로 올리고, 늘 "시험판(pre-release)"·"최신 아님"으로 올려 README의 Windows 내려받기 링크를 지킨다.
- **매 단계 끝에 수업에 쓸 수 있는 판**을 남긴다: 태그와 zip을 보관해서, 수업 날 아침 문제가 생기면 한 단계 전으로 되돌린다.

## 모델과 크레딧 규칙

- **한 세션 = 한 줄**: 위 표의 한 줄이 새 대화 하나다. 모델은 **시작 전에** 고르고, 중간에 바꾸지 않는다. 바꾸면 새 모델이 대화 전체를 처음부터 다시 읽는다.
- **Opus는 결정할 때만**:
  - S1b(시험 설계), S1c(결정·설계도), S10(서명), S11(검토), 그리고 풀리지 않는 버그.
  - 노력 "최대"는 S1c 한 번이면 충분하다. 나머지는 "높음".
- **Sonnet이 만들고, 만든 세션이 빌드·점검·커밋까지** 한다. Haiku는 절차서(`RELEASE.md`)대로 하는 배포·버전 올리기·오타 고치기 같은 **새 세션**에만 쓴다.
- **막히면 넘긴다**: 같은 증상을 Sonnet이 두 번 고쳐도 안 되면 멈춘다. 새 Opus 세션에 진단 기록, 실패한 점검, 관련 파일 하나만 준다.
- **긴 실습 뒤에는 새 세션**: 선생님이 45분 시험하는 동안 대화 캐시가 식는다. 결과는 파일에 적고, 짧은 새 세션이 그 파일만 읽게 한다(S1b → S1c).
- **적게 읽기**:
  - `focus-draw.ahk`(4,475줄)와 `NOTES.md`(155KB)는 통째로 읽지 않는다. README는 절 단위로, 이 문서는 150줄 안팎으로 유지한다.
  - 끝난 단계는 `mac/HISTORY.md`로 옮긴다(S1a에서 만든다).
- **그림 대신 글로 확인**:
  - `build.sh --test`는 성공하면 한 줄만 찍는다. 실패하면 바뀐 장면 이름만 알려준다.
  - 선생님께는 축소한 기준 그림 한 장을 보낸다.
- **빌드는 가볍게**: 고치는 동안은 `--quick`(애플 실리콘만), 커밋 전 한 번만 전체 빌드와 점검을 한다.
- **다시 확인할 일이 생기면** "점검 장면을 하나 추가해줘"라고 한다. 한 번 만들면 이후 모든 단계를 지켜 준다.
